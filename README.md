## 侍 projetos selecionados

<br>

**[rag-local-ollama-chroma](https://github.com/lellisz/rag-local-ollama-chroma)**
RAG local sem framework — recuperação híbrida rodando 100% on-device com **Ollama** + **ChromaDB**, sem LangChain/LlamaIndex de por meio. Construído como projeto de validação para a certificação **AWS AIF-C01**, isolando cada peça do pipeline (chunking, embedding, retrieval) para entender o que cada camada realmente faz.
`Python` `Ollama` `ChromaDB` `RAG`

<br>

**[lora-portfolio-report](https://github.com/lellisz/lora-portfolio-report)**
Portfólio de ML/agentes: fine-tuning com **LoRA** e avaliação multi-agente do resultado — o próprio pipeline de avaliação é feito por agentes especializados, não por métricas isoladas.
`Python` `LoRA` `Multi-Agent Evaluation`

<br>

**incident-copilot** <sub>· em desenvolvimento</sub>
Agente de resposta a incidentes construído em **LangGraph**, com checkpointing em **Postgres + pgvector**, retrieval híbrido (vetor + full-text via RRF) e reranking por LLM-as-judge. Modelos locais (Ollama) e cloud (Gemini, Bedrock Claude) coexistem por nó, cada um escolhido pelo trade-off custo/qualidade daquela etapa — não por padrão.
`Python` `LangGraph` `Postgres/pgvector` `AWS Bedrock`

<br>

## 学 princípios

- decisão arquitetural é minha; agentes de IA executam sob supervisão, nunca no piloto automático
- todo projeto de portfólio existe para provar um conceito específico — não para preencher um README
- experimento antes de concluir: rodar com e sem RAG, medir, só então decidir
